Test standards. Cite the ID in your summary where a choice depends on one.
T1 Kind: unit, integration (runs in CI, no running service) or e2e (the real stack, model, agent or API); one kind per test.
T2 Placement: a new case goes in its module's mirror test file; a new test file only for a new logic file; one subject, one file.
T3 Name: a test name is a sentence stating one behaviour; test file base names are unique.
T4 Surface: test the public surface; import no private name.
T5 No wall-clock assertion: state speed as work done.
T6 No sleep, no unbounded wait: wait on an event with a deadline.
T7 No fixed port, no unjoined thread.
T8 Per-test identity: ids, paths and names come from fixtures.
T8a Isolation comes from shared fixtures; the same setup in several files is a missing fixture.
T9 A test passes alone, in any order and under any worker count.
T10 Inject the clock and randomness.
T11 No network but loopback in a unit test; no real agent.
T12 Read only tracked files.
T12a Touch only your own project's files.
T13 Read a changing external value through one helper.
T14 Set the environment you read.
T15 Warnings that hide a bug stay errors.
T16 Fit the time budget; a test that needs more is a scan or is split.
T17 A whole-repository scan is an integration test and scans once.
T18 A child test run's code is a file, not a string.
T19 One behaviour: arranged, acted, asserted.
T20 Assertions bite: removing the behaviour fails the test.
T21 Parametrise, do not copy; define a helper once.
T22 No test of a test.
T23 A fake satisfies the seam (a Protocol); do not mock an internal.
T24 Generated data is regenerated by the change that alters its generator.
T25 A missing environment is a skip or a configuration error, never a failure.
T26 A reorganization changes tests only mechanically.
T27 Integration tests go in integration/, e2e tests in e2e/.
