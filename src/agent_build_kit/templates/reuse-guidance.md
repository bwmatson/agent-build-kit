**Reuse before you write.** Search for an existing helper, constant, pattern, fixture or test helper before adding one, and use or extend it. To find where this repository keeps what is reusable, read what the neighbouring code imports; look in the modules and directories named for shared code (`utils`, `common`, `shared`, `lib`, `helpers`, `core`, `internal`) and in the test runner's usual places for fixtures and test support; follow the language's own conventions, or where the language is unfamiliar, common ones: a shared module beside its callers and test support in one place. Search by the behaviour of what you are about to write, such as its key literal, pattern or call, as well as by name, because an existing helper rarely has the name you would give it.

Write logic needed in two places once, including two variants of one feature such as two hosts, backends or runtimes, and derive a value from one source rather than computing or recording it twice. Give calls that must change together one function. Use the shared test support: a test helper needed in a second file moves to the shared place instead of being copied. Follow the neighbouring idiom, delete what your change makes dead, and leave no old way beside a new one.

Stay within the change: remove the duplication it would introduce or touches, do not rewrite unrelated code, and say in your summary when reuse needs a larger refactor so it can be recorded.
