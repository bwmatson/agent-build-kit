- [ ] 2.5 Add a `CHANGELOG.md` entry under Unreleased: unit worktrees are keyed by the repo's name in `abk.yaml`, an existing worktree is found through git and used where it is, one checked out elsewhere is refused, a sanitiser collision is refused, and `abk doctor` reports worktrees under another folder.
- [ ] 2.6 Add `docs/runbooks/move-the-unit-worktree-root.md` and add it to the runbook list line of `README.md`. Its first line is `Follow it only after group 1 and group 2 of unit-worktrees-are-keyed-by-the-repository-name are built and merged.`, as the other runbooks open, then "Nothing in it is read by the pipeline. Tick the boxes as you go." Steps, each a checkbox: (1) stop the timers (`abk install-timers --remove` or `systemctl --user disable --now` of the tick and track timers) and wait for the tick and track services to be inactive and `abk status` to show no running unit; never kill a running one; (2) `git worktree list` in each repo and note the unit worktrees under the old root; (3) edit `abk.local.yaml` (`planning.worktree_root`) to the new folder, or remove the key so the default `<data home>/<repository name>/worktrees` applies, and keep the new folder outside the repository; (4) for each unit worktree whose unit is not running, `git worktree move <old> <new-root>/<repo name>/<sanitised branch>`, or `git worktree remove <old>` for a clean one (the branch keeps the work; never `--force`); (5) `git worktree prune`; (6) `abk doctor` shows `unit worktrees` ok; (7) restart the timers. Rollback: stop the timers, restore the old `worktree_root`, `git worktree move` the worktrees back; any left where they are keep being used because they are found through git.
