# pipeline-state-lives-outside-the-repo

In an in-repo installation (a repository that is its own planning repo) the pipeline's state sits in `runs/` of a checkout: it is dirty in the pipeline worktree, absent from the working copy's history and in the way of the worktree's fast-forward sync. This change makes the state application data. By default it lives in `~/.local/share/<repo>/planning/state/` (the generated pages under `state/pages/`), the pipeline worktree moves to `~/.local/share/<repo>/planning/worktree/`, the tracks' run logs and `tracked-issues.md` stay in the repository under the new `planning.reports_dir` (default `docs/reports`), and `abk init`, `abk doctor`, `abk planning split` and the documents follow. Settings: `planning.home`, `planning.state_dir`, env `ABK_PLANNING_HOME` and `ABK_STATE_DIR`. Priority 1.
