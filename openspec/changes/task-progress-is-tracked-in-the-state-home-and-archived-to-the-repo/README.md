# task-progress-is-tracked-in-the-state-home-and-archived-to-the-repo

The pipeline ticks a change's `tasks.md` and writes its `follow-ups.md` inside the pipeline worktree, so every tick dirties tracked files there, a person's later edit of `tasks.md` on the default branch stops the worktree's fast-forward sync, `*.md.lock` files pile up untracked inside `openspec/changes/`, and nothing commits the result of `openspec archive`, so the default branch never shows a merged change as archived. This change keeps the ticks and follow-ups in a tracking copy under the state directory (read for progress, never edited by a person), moves the change locks out of the repository, and makes the archive step write the final files back, run `openspec archive` and commit the result through the planning publish path. Priority 3; it builds on `pipeline-state-lives-outside-the-repo` (the planning home).
