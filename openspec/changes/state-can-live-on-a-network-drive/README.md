# state-can-live-on-a-network-drive

A person can point `planning.state_dir` (or `planning.home`) at a network share and the pipeline stays correct, on the one supported topology: one pipeline host, the durable state on the share. A new `planning.local_dir` (default `<planning home>/local`, `ABK_LOCAL_DIR`, `abk.local.yaml`) keeps what cannot be shared on local disk: the checkpointer's SQLite database, the branch, repo and environment locks, the leases and the e2e-test lock. `file_lock` waits a bounded time instead of for ever, atomic writes are named per host and process and synced before the rename, and leases and lock records carry their host and are never taken over from another one. `abk doctor` (and the tick, cheaply, when the state is not on a local filesystem) probes that two processes really exclude each other there and refuses, naming the mount type and the fix, when they do not. Two hosts running ticks at once stays unsupported and is said so. Priority 4: the last change in the flow.
