# config-migrate-moves-machine-settings-to-the-local-file

`abk config --migrate` edits only the one abk.yaml in force (renames `limits`, moves the three scheduling settings and `max_unit_lines`, renames old test-kind keys, moves a flat `models:`). On 2026-10-21 the split of this installation's `abk.yaml` into `abk.yaml` and `abk.local.yaml` was done by hand with a one-off script, although `docs/configuration.md` ("Which file holds a setting") says which setting belongs where and `abk doctor` already warns about most of them. This change makes the same command do that move, by text, in agent-build-kit: the settings of one machine (a repo's checkout path and account, a deploy key path, the worktree root, `project_limits`, a runtime's accounts and absolute program paths, `e2e_available`, and a `verify.env` value holding a home path) are lifted with their comments from a git-tracked `abk.yaml` into `abk.local.yaml`, keeping every other key of an entry where it is. The defaults a team may commit (`runtimes.<name>.limits`, `e2e_schedule: off`, a split's `hold`) move only with `--include-defaults`. The list of machine settings becomes one table that `abk doctor` and the migration both read, and the doctor's messages name the command. The merged configuration is compared in memory before and after and must be equal; an existing local key is reported and left; both files are written both-or-neither (the local file first, the tracked one second, the first restored if the second fails); `.gitignore` is made to cover the local files; a notice names the running units, because a write fails their builds; the command never commits. Normal priority (3).
