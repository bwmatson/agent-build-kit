## From `github-native-stacks/1`

- The check for a branch the host moved appears twice with almost the same code: once in `events.build_restack` (the branch that handles a lost push record, then the adopt, `record_push`, `record_approval("")`) and once in `wiring.build_push`. The two copies already differ slightly: `build_push` reads `here` with `rev-parse --verify` and only calls `remote_head_of` when `last_pushed` is set, while `build_restack` compares `head_of(repo, branch)` instead. Put this in one named helper in `restack.py` that returns 'unchanged / lost record / adopted', and have both callers use it. That same helper is also where a bounded retry for the second `HostMoved` in `_spend_rounds` could go, which is already listed in follow-ups.md.
- `wiring.build_push` now runs `git ls-remote` against `push_target` before every push that has a `last_pushed`. That adds one network call per push. It is correct, but `docs/architecture.md` should say so in the push step, so nobody later removes it thinking it is redundant.
