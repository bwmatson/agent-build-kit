# repo-wide-guards-treat-planning-content-as-data

When this repository became its own planning repo, `openspec/` was committed beside the code, and the suite's repo-wide guards began reading it: five of them fail on history and requirements that were never theirs to judge (archived changes naming removed keys and old test modules, neutral tilde examples in specs, three dated lines), and two telemetry tests fail on a person's ignored `.env`. This change gives every repo-wide guard one helper that says which tracked files it reads, with the specification folder derived from the configuration; keeps the public-content rule where the existing specification puts it (the leak scan still reads `openspec/`); skips planning content for the guards that police the documents; adds an issue-reference scrub as a safety net; and cuts the suite off from the checkout's `.env`. The pipeline's state is moving out of the repository in a separate change; nothing here depends on a `runs/` path. Priority 1: the main branch's checks are red until it lands.
