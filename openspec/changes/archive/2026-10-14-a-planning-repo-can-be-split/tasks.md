# Tasks

Acceptance: none — every behaviour here is a file copy, a record copy, a classification or a text edit between two temporary installations, and each is proved by a tier-1 test over temporary directories with the command run in process; no consumer drives a surface this change builds beyond what those tests drive.

Priority: 3

## 1. [agent-build-kit] [tier1] The split is planned: what moves, what stays and what is mixed

Done when a function reads a source installation's working tree and returns, for a repo (and optionally a project), the moved, staying, mixed, unreadable and unclassified changes and archive entries, the moved, shared and unowned specs, the moved and blocking units, and the uncommitted files it read. Estimate: about 340 changed lines.

- [x] 1.1 Test: in `tests/split/test_select_changes.py`, over a temporary source with changes tagged `[app]`, `[lib]` and both, `--repo app` classifies them moved, staying and mixed; with a repo declaring project `web`, `--project web` counts only `[app/web]` groups and a change with `[app]` groups is mixed; an undeclared project is refused naming the declared ones; an archive entry is classified by its own `tasks.md`, one with none is unclassified, and a heading with no repo tag is unreadable and neither moved nor staying.
- [x] 1.2 Test: in `tests/split/test_select_specs.py`, a capability whose only delta is in a moved change is moved, one with deltas in a moved and a staying change is shared and stays, one no change touches is unowned and stays, `--spec <capability>` moves an unowned one, and a name that is no capability is refused.
- [x] 1.3 Test: in `tests/split/test_select_mixed.py`, a mixed change is listed with each group's repo and project; `source` keeps every mixed change and its archive entries; `destination` moves them whole; `destination` is refused naming the repo and the change when a group is tagged for a repo the destination does not declare; `both` is a usage error; with no value the plan refuses.
- [x] 1.4 Test: in `tests/split/test_select_units.py`, over a temporary store, units of moved changes are selected and others are not; a unit carrying a `joined` member of a staying change is an error naming the unit and both changes; units in `running`, `in_review` and `held` are errors naming the state; `merged` and `failed` units are selected.
- [x] 1.5 Test: in `tests/split/test_select_working_tree.py`, an untracked change is classified, a file deleted in the tree is not read, a modified, an untracked and a deleted file under the specs directory print as `M`, `??` and `D` with a count of 3, and a source outside git says so and lists none.
- [x] 1.6 Add the `agent_build_kit/split/` package with `select.py`: a frozen `SplitPlan` model and `plan_split(source, repo, project, allow_mixed, specs)` reading the files with `validate_tasks`, classifying changes, archive entries and capabilities, and the units through `UnitStore.all()`; the refusals are a tuple of frozen `Refusal` models with a kind (a `StrEnum`) and a line.
- [x] 1.7 Add `uncommitted(source)` in `split/select.py`, running `git status --porcelain` limited to the specs and state paths, and return its lines for the plan.

## 2. [agent-build-kit] [tier1] The copy: files, unit records and plan records, a dangling edge refused, and scrub

Done when a plan is carried out against a destination installation: files copied without overwriting a different one, unit records imported through a new store method with their plan records, every dangling edge named before any write, and `--scrub` applied to moved text and to the free text of the records. Estimate: about 340 changed lines.

- [x] 2.1 Test: in `tests/split/test_copy_files.py`, a moved change is copied file by file with its bytes and mode and without lock files; an identical destination file is left and its modification time does not move; a different one is a conflict naming the path with nothing written.
- [x] 2.2 Test: in `tests/pipeline/test_unit_store_import.py`, `import_units` keeps every field of a merged unit (state, history, branch, pull request, flag, calibration) and writes the store's own format; an equal record is skipped, a differing one with the same id is a conflict naming the id and writes nothing; `remove_units` removes the named ids under the lock; both run under the store's exclusive lock and call `on_write`.
- [x] 2.3 Test: in `tests/split/test_copy_plans.py`, a moved change's plan record is written to the destination with `attempts` 0, `ok` true and the hash `sha256(specification_text(destination text))`, so a scrubbed change keeps a matching hash; a change with no source record gets none; and `abk status` and `abk report` print for a copied unit whose `run_log` names a file the destination lacks.
- [x] 2.4 Test: in `tests/split/test_dangling_edges.py`, a moved unit whose `depends_on`, `needs` or `joined` member names something neither moved nor in the destination is one error line naming the unit, the field and the target, all listed, with nothing written; a target already in the destination is fine; a `Needs: other group 2` line in a moved `tasks.md` whose change stays is an error naming the change; a staying edge into the moved set is a warning, and an error with `--remove`.

- [x] 2.6 Add `import_units` and `remove_units` to `UnitStore` in `pipeline/unit_store.py`, both under `_exclusive` and writing through `_write`.
- [x] 2.7 Add `split/copy.py`: copy the files, import the records, write the plan records through `record_plans`, with the preflight that finds every conflict and every dangling edge before the first write.
