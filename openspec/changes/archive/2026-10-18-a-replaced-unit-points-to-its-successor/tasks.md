# Tasks

Acceptance: none — the field, its write, the resolver, the readers, the repoint, the recorded waits and the status lines are decided by stored units built with a factory in a temporary store, a stub of the tasks files and a fixed clock; nothing reaches a model, a forge or a host, and the failure itself is a store state a test writes.

Priority: 0

## 1. [agent-build-kit] [unit-test] A replaced unit records its successors, and one function reads a unit's dependencies through them

Done when `Unit` has `superseded_by`, left out of the stored record when empty and empty for a record that lacks it; `upsert`, `unplan_vanished` and the backfill's shared helper record the successors of each unit they set `unplanned` or find `unplanned` or `retired` with none, in the same write; a unit the plan asks for again loses the field; `successors_of`, `resolve_replaced` and `current_dependencies` exist in `pipeline/units.py` and are the only code that follows the field. It builds only on code already in the main branch and depends on no unbuilt unit; where other changes touch the same lines a rebase resolves it. Estimate: about 330 changed lines.

- [x] 1.1 Test: `tests/pipeline/test_units_current_dependencies.py` asserts, with `tests.factories.stored_unit`, that `resolve_replaced` returns the id for a live unit, an absent id and a replaced unit with no successors; the successor for one; the last of a chain `a -> b -> c`; both of a split, once each in order; the id itself for two units naming each other; a read that stops at the eighth link of ten; and the merged successor unchanged. That `current_dependencies` keeps order, de-duplicates, never contains the unit itself, and leaves a cross-repo entry as it is.
- [x] 1.2 Test: `tests/pipeline/test_unit_store_successors.py` asserts `successors_of` includes a planned, running, merged and satisfied carrier (joined groups too) and leaves out `unplanned`, `retired`, `closed` and the unit itself; a join of `x/3` and `x/4` into `x/5` through `upsert(change="x")` leaves both `unplanned` with `("x/5",)` and a history entry `replaced by x/5`; a split gives both; a dropped group gives an empty field absent from the written file; a set field is not overwritten; a unit the plan contains again is `planned` with the field empty and its other runtime fields kept; a replaced unit not in the plan, and a retired one, keep theirs; `unplan_vanished` records the same.
- [x] 1.3 Test: the same file asserts a units file written without the key loads with the field empty and is written without it, a record that holds it loads, and `tests/pipeline/test_unit_store_foreign_fields.py` (or the file beside it that tests `_tolerate_other_releases`) still refuses an unknown key with a value.

## 2. [agent-build-kit] [unit-test] Every reader of a unit's dependencies uses the resolver, a tick repoints the stored edge, and a recorded wait follows the successor
