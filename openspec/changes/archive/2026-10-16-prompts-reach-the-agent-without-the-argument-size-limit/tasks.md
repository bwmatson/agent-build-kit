# Tasks

Acceptance: none — the transport and the omission are decided by the argument list a runtime builds, the bytes a fake `claude` executable reads on its standard input, and a planning prompt built from a hand-made store; no behaviour a consumer drives changes, and the first real replan after this lands is the live confirmation.

Priority: 1

## 1. [agent-build-kit] [unit-test] The Claude Code runtime delivers the prompt on standard input, chosen and size-checked in one place

Done when `build_argv` has no prompt in it, `spawn` and `stream_run` hand the prompt to the process as standard input, a runtime declares how it carries a prompt, one function checks a prompt against that transport's safe size, and an oversize prompt fails before any process starts with a message naming the call, the size, the limit and the transport. Estimate: about 300 changed lines.

- [x] 1.1 Test: `tests/runtimes/test_prompt_delivery.py` runs `spawn` against a stand-in executable (a script written to a temporary directory that writes its standard input to a file and prints a result event) and asserts a 300,000-byte prompt (non-ASCII text included) arrives whole and unchanged on its standard input, the reply is parsed into the `AgentResult` text, `-p` is in its arguments and the prompt is in none of them, and the same holds with a progress callback (the streamed path) and with `resume_session` and `keep_record` set.
- [x] 1.2 Test: `tests/runtimes/test_prompt_delivery.py` also asserts a five-word prompt gives the same arguments as before apart from the prompt's absence and the same `AgentResult`, the order of the other flags is unchanged, and a prompt of 100 bytes is delivered on standard input like any other.
- [x] 1.3 Test: `tests/runtimes/test_prompt_transport.py` asserts the check allows an `argument` prompt of exactly 100,000 bytes and refuses one of 100,001, allows a `stdin` or `protocol` prompt of exactly 2,000,000 bytes and refuses one of 2,000,001, counts UTF-8 bytes (50,001 two-byte characters are refused on `argument`), and that the refusal is a `PromptTooLarge` error whose first line reads `the <role> prompt is <size> bytes; the <transport> transport carries at most <limit>`, naming the change when the request names one, and that no process was started.
- [x] 1.4 Test: `tests/runtimes/test_prompt_transport.py` asserts the Claude Code runtime declares `stdin`, the ACP runtime declares `protocol`, a stand-in runtime declaring `argument` is refused at 100,001 bytes, `run` raises `PromptTooLarge` for it before its executor is called, and the `OSError` text `Argument list too long` appears in no message.
- [x] 1.5 Test: `tests/runtimes/test_prompt_delivery_callers.py` asserts, with a recording executor, that a restack, a review, a track phase and the planner request each reach the executor with their prompt as the input and not in the argument list (so no caller builds its own argv), and that `refresh_login`'s fixed prompt is still an argument.
- [x] 1.6 Add `PromptTransport` (a `StrEnum` of `argument`, `stdin`, `protocol`) with each transport's safe size, a `prompt_transport` attribute on the runtime protocol and both runtimes, `PromptTooLarge` and the one check function in `runtimes/base.py`; the check runs at the start of `run` for every runtime.
- [x] 1.7 Take the prompt out of `build_argv`, give `spawn` an `input` for it that reaches `subprocess.run` (`input=`) and `stream_run` (a pipe on standard input, written and closed before the output is read, from a thread so a large prompt cannot block on a full pipe), and update the executors that tests inject to take the new argument.
- [x] 1.8 Confirm the place design.md marks UNVERIFIED and correct the design where the code says otherwise.

## 2. [agent-build-kit] [unit-test] The planner leaves out landed units of other changes and names the parts of a prompt that is still too large

Done when the planning round passes the planner every unit that can still affect a plan and one summary line for the merged and satisfied units of other changes, and a planner prompt over the safe size fails as a planning failure whose reason names the change and the size of each part. Estimate: about 260 changed lines.

- [x] 2.1 Test: `tests/pipeline/test_planner_in_flight.py` with a store of 3 merged and 1 satisfied unit of other changes, 2 merged and 1 running unit of the change being planned, 1 failed, 1 held and 1 in-review unit of other changes and 2 planned units of other changes asserts the prompt lists the 2 merged and the running unit of this change, the failed, held, in-review and planned ones, none of the 4 landed units of other changes, and one line `4 merged or satisfied units of other changes are in the trunk and omitted` in their place; with none to omit the line is absent; and `(built by <unit id>)` still marks the groups of this change's merged units.
- [x] 2.2 Test: `tests/pipeline/test_planner_in_flight.py` also asserts a plan that depends on an omitted merged unit still passes the plan check (its id is in the store's `known` ids), a `Needs:` line naming a group an omitted unit built still yields its edge, and a prompt built from the store of 360 merged, 140 planned and 12 other units is under 100,000 bytes with the 38 KB `tasks.md` of the largest open change.
- [x] 2.3 Test: `tests/pipeline/test_planner_prompt_size.py` asserts a planner prompt of 2,000,001 bytes fails with a `PlannerError` whose first line names the change, the size and the limit, and whose following lines give the size of the template, the change's `tasks.md`, the relationships, the calibration section and the in-flight list; that no process is started; and that a 300,000-byte planner prompt (with the transport `stdin`) is sent whole and its reply parsed into a plan.
- [x] 2.4 Test: `tests/cli/test_replan_prompt_too_large.py` asserts `abk replan` on such a change records the attempt, prints `failing 1/3: <the first line>` in its listing (the reason is the first line, no `OSError` and no type prefix), a second and a third run count 2/3 and 3/3 and then `given up`, and `abk replan --failed` plans it again; no new retry path is added (the test reads the attempts only).
- [x] 2.5 Build the omission in the planning round where `context` is made (`cli/pipeline.py`), keeping `in_flight_item` as it is, and make `build_prompt` print the summary line and return the sizes of its parts; raise the part-naming `PlannerError` in `_ask` before the request is made, using the check of group 1 for the limit.
- [x] 2.6 Confirm the sizes in the proposal against `runs/units.json`'s shape in the tests, and correct the proposal where they differ.
