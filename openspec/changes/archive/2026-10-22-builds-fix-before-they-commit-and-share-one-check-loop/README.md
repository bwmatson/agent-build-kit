# builds-fix-before-they-commit-and-share-one-check-loop

Unit `usage-is-estimated-from-recorded-cost/1` (repo agent-build-kit) failed on 2026-10-22 with "static checks failing and fix round 1 changed nothing". The first static check failed only because the repository's `ruff format` hook reformatted a file in place (a hook that edits a file makes `pre-commit run` exit non-zero); the second run would have passed, and the fix agent rightly edited nothing. The stub check loop compares the tree before and after the agent's step, saw no change and failed the unit. This change removes that class of failure at its cause and merges the two copies of the loop that caused it. First, each profile gains a `fix_command(files)` method (python-uv: the pre-commit hooks over the unit's changed and untracked files, status ignored, at most two passes; node-npm: `npx oxfmt` and `npx oxlint --fix` over the unit's source files, per project directory), and the pipeline runs it, with no model call, before every commit a build makes: the tests commit (ahead of the static check), the implementation commit, each checks-loop `fix:` commit, and the old build's tests and implementation commits. Second, the stub loop and the checks loop share one check-and-fix routine that takes the check as a callable returning `(ok, output)`, the fix prompt, the commit rule and the feedback source; the "changed nothing" stop and `max_check_rounds` stay exactly as they are, now in one place. A repo may replace the command with `repos.<name>.tests.fix_command` (policy, in `abk.yaml`). Emergency lane (priority 0).
