## From `per-unit-run-logs/1`

- The `Co-Authored-By` trailer is still on the branch, now at commit 13456f9 (the hash in follow-ups.md, 52af856, predates the move onto the updated base). CLAUDE.md says commits here carry none. Drop it at merge: a squash merge's default message concatenates the commit bodies, so the trailer has to be deleted from the squash message by hand or the commit reworded first.
- `test_the_files_lines_carry_the_stamp_the_tick_prints` (`tests/pipeline/test_cli_pipeline.py`) does not really prove the stamp is taken once. It does pin that the file line carries a `[HH:MM:SS]` stamp, but at one-second resolution two separate `stamp()` calls would almost always agree. To pin it, monkeypatch `cli.stamp` to return a different value on each call and assert the printed and written stamps still match.
- The closing `outcome:` line has no time of its own. When a run reaches `end()`, the stamped line above it gives the end time. A run that leaves `_build` without reaching `end()` (a `KeyboardInterrupt` or `SystemExit` passing through the `finally`) closes with a bare `outcome: interrupted` and no end time. If that matters, have `RunLog.close` append the time as a suffix (for example `outcome: interrupted (at HH:MM:SS)`) on that path only, so the exact-line assertions for the other outcomes stay as they are.
- `remove_change_logs` (`src/agent_build_kit/pipeline/run_log.py`) wraps the whole loop in one `try`, so the first `unlink` that fails (a directory sitting where a log should be, or a permission error) silently leaves every later log of that change in place. Put the `try` around each `unlink` so the rest are still removed, and keep a separate catch around `iterdir()`.
- In `RunLog.__init__`, `_prune` runs inside the same `try` as the header write. A prune failure therefore reports `run log … not written` and stops all writing to a file that was created, and `_build` then does not record its name. Give the prune its own guard so a failed prune only leaves old files behind.
